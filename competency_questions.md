What is the domain the ontology will cover? 
- Governance of AI/algorithms in the Dutch public administration
For what are we going to use the ontology? 
- Auditing of algorithms
For what types of questions the information in the ontology should provide answers? 
- What obligations apply to this AI system?
- How can these obligations be met?
- Where do these obligations come from?
- What is the overlap between obligations from different sources? Is compliance with document A = compliance with document B?
Who will use and maintain the ontology?
- Auditors at ADR

Competency questions:
- What risk class does this AI system fall under?
- Which obligations apply to an AI system of risk class X used by a public body for purpose P?
- Which source does obligation O come from?
- Which measures or evidence demonstrate compliance with obligation O?
- Which obligations from source A cover the same requirement as obligations from source B?
- Which obligations does document D (eg AIIA) provide evidence for?
- What documents can provide coverage for (an) obligation(s)?*
- If a system meets obligation O1, which other obligations does that also satisfy?*
- Which obligations apply in the Dutch context only, not in the AI Act itself?
- Which obligations are legally mandatory, and which obligations are required by the organization?
